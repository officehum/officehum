# Gateway (RASF-3105)

**Goal:** `@officehum/gateway`, an office's network edge: authenticated WebSocket and HTTP clients,
permissions, forwarding to the runtime child process (RASF-3104), events fanned back out, and the
runtime restarted if it dies, without dropping a client.

**Spec:** Linear RASF-3105, under RASF-3101. Protocol: `docs/design/gateway-protocol.md`.

## Files

| File | Responsibility |
| --- | --- |
| `packages/protocol/src/messages.ts` | `hello` gains an optional `token`: the first-frame credential for WebSocket clients that cannot set a header (browsers). |
| `packages/gateway/src/config.ts` | `gateway.json`: listen address, TLS file paths, the runtime command, JWT issuer/audience, permissions. Validated with every problem and its path. No secrets. |
| `packages/gateway/src/auth.ts` | `verifyToken`: JWT (`jose`) with the public key from `OFFICEHUM_GATEWAY_JWT_PUBLIC_KEY` → `principal { id: sub, roles, approvalLimit }`. Requires `exp`. |
| `packages/gateway/src/permissions.ts` | Deny-by-default rules for `submit` (roles → agents), `approve` (roles, limit) and `abort` (roles). |
| `packages/gateway/src/supervisor.ts` | Spawns the runtime, always drains its stdout, restarts it with backoff 1 s → 30 s, reports up/down. |
| `packages/gateway/src/router.ts` | The core: rewrites commands (strip client `principal`, attach the token's, gateway ids), routes replies by id and events by request, owns the client-facing `seq`, replays, re-subscribes after a restart. |
| `packages/gateway/src/server.ts` | `startGateway`: node `http`/`https` + `ws`; WebSocket sessions; HTTP `POST /v1/submit`, `GET /v1/requests/:id`, `GET /v1/requests/:id/events` (SSE), `GET /healthz`; audit log. |
| `packages/gateway/src/bin.ts` | `officehum-gateway --config gateway.json`. |

## Decisions

- **`node:http` + `ws`, not Fastify.** Four routes do not need a framework, and every dependency is
  attack surface at the edge. `ws` 8.22.0 and `jose` 6.2.13, pinned exactly, both dependency-free.
- **The gateway owns the client-facing `seq`.** The runtime keeps events in memory and numbers a
  resumed request from 1 again (RASF-3104), so the gateway renumbers: each request's events get a
  gateway seq that only grows, across runtime restarts, and runtime events already seen in the current
  runtime generation are dropped. `settled` is forwarded once. SSE `Last-Event-ID` is that seq.
  Gateway memory only; a gateway restart is RASF-3106.
- **Auth.** A token's `sub` is the principal id, `roles` (array of strings) its roles, `approvalLimit`
  (number) optional. `exp` is required; `iss`/`aud` are checked when configured. Algorithms follow
  the key type (RSA → RS256, P-256 → ES256, Ed25519 → EdDSA). A WebSocket client authenticates with
  `Authorization: Bearer` on the upgrade or `hello.token` as its first frame; until then every command
  gets `unauthorized`.
- **Permissions.** `submit` checks the agent; `approve` checks role and limit (`approve` itself is
  still `not_found` at the runtime until RASF-3108); `abort` checks role. `subscribe`, `get_state`,
  `list_agents` and `ping` need only a signed-in principal: the runtime scopes requests to their
  principal, so nobody can subscribe to another's.
- **Supervision.** Any exit the gateway did not ask for restarts the runtime with backoff; the backoff
  resets after 60 s up. While it is down, commands get `busy`. After it says `welcome`, every unsettled
  request the gateway knows is re-subscribed.
- **Slow clients.** Every client send is non-blocking; a WebSocket whose buffered output passes a limit
  (default 8 MiB) is closed, so one slow consumer never holds memory or other clients hostage, and the
  runtime's stdout is decoded regardless.
- **Audit log.** One JSON line per command to stderr: time, principal id, action, agent, request id,
  outcome. No bodies, no tokens.

## Tests (first)

Unit: config, auth (good, expired, wrong key, missing claims), permissions. Gateway with a fixture
runtime child: WebSocket submit → settled; unauthenticated / bad token → unauthorized; no permission →
forbidden; a client-sent principal replaced; SIGKILL the runtime mid-request → client stays connected,
runtime restarts, `settled` arrives, unsafe tool ran once; SSE with `Last-Event-ID`; a paused client
does not stall another; `busy` while down; `/healthz`.
