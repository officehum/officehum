# Audit part 2: decisions and plan

Works through part 2 of `docs/audits/2026-11-11-codebase-audit.md`. Item numbers below (A1, B7, …)
are that document's. Each item has the decision taken; "left" items stay open and are filed as
issues. The aims are, in order: correctness of guardrails, behaviour that holds at larger sizes, and
features that are built but unreachable.

## Rules for everyone working on this

- Build exactly the decision written here, the simplest way that fits the existing code. No new
  options, layers or config beyond what a decision names. Follow the patterns of the nearest code.
- Fit, not bolt-on: if a decision only fits with a refactor larger than the files it names, stop and
  report instead of wedging it in.
- Failing test first, then the fix. Cover replay and restart for any tool that writes. No network
  and no real model calls in tests.
- Repository hard rules in `AGENTS.md` apply (Pi Durable runtime calls only in `@officehum/office`,
  `replay` stated in code and manifest, `output` not `content`, guardrails as code, no secrets).
- Do not touch `AGENTS.md`, `.github/`, version pins, or anything labelled Deferred (codemode,
  RASF-3190) or the worker sandbox (RASF-3111).
- User-facing docs change with behaviour, in the same commit.

## A. Bugs

| Item | Decision |
| --- | --- |
| A1 nested wait deadlock | Split the poller into admit and settle so a delegate's turn never blocks delivery of its child's events. Unskip the red-team case. |
| A2 recovery skips guards | `recover()` re-runs budget and hop guards on a `pending` row before delivering; a row that now fails is refused the same way a fresh dispatch is. |
| A3 spend rounds to zero | Ledger records cost in a finer integer unit (micro-dollars), with a migration of existing rows (cents × 10,000). Ceilings stay configured in dollars and are compared in the fine unit. Display rounds at the edge. |
| A4 inbound email 503 | Terminal rejections (auto-reply, DMARC failure, other non-retryable) are recorded and answered 2xx; only transient failures answer 5xx. |
| A5 `/reload` changes model | A saved conversation keeps its provider and model across reload; the overlay's model applies to new conversations only. |
| A6 local board completion | Only the ticket's assignee may complete it; the dispatcher may not complete its own dispatch. The test uses the real claim path. |
| A7 stale wait result | Clear the wait on timeout and on consumption, so a later wait on the same key never reads an old result. |
| A8 role factory | `declined-*` evals expect "approval requested, tool not executed"; all validation (word limit, overlay) runs before anything is written. |
| A9 `agent_inbox` past 100 | Filter by role in SQL, then limit. |
| A10 unbounded request maps | Evict a request's record when it reaches a terminal state and its replay window closes; bound both maps. |
| A11 request id length | Scoped ids are kept within the protocol limit by construction (hash the over-long part); nothing the runtime emits can be rejected by its own gateway. |
| A12 Paper lease and commit | Replay ledger is consulted before lease expiry; multi-output commits are all-or-nothing (stage, then rename). |
| A13 Excel `setStyle` | Merge given fields into the existing font and alignment. |
| A14 Word `addComment` | A block anchor works, or is refused with a document error naming the anchor; never a bare exception. |
| A15 Excel reference checks | Diff uncapped lists and cap only what is shown; recognise columns only in valid cell references; resolve named ranges; compare sums with a tolerance. |
| A16 oversized replies | Trim at the level the keys really live at; if the reply still does not fit, return `ok: false` with what to narrow. |
| A17 Support | Escalation requires a sender matched to the case's client; a proposed credit is reported as proposed until someone is asked; the re-clean refusal states the dates the right way round. |
| A18 People Ops | A declined time-off ask restores the notice count. |
| A19 Front Desk | A `pending` approval is not a decline: the reply waits; an approved discount is recorded on the booking. |
| A20 Bookkeeper | A not-yet-due invoice reads "due in N days". |
| A21 Client | A failed second `watchApprovals` listener is removed; a `busy` answer to the re-watch is surfaced and retried. |
| A22 `handToPerson` | Swallow only the "already moved on" error; rethrow everything else. |

## B. Guardrails

| Item | Decision |
| --- | --- |
| B1 Marketing checks | Claim, testimonial and unsubscribe checks move into the tool layer so they run with any desk. |
| B2 Bookkeeper recorder | "Who recorded this bill" comes from the verified sender; the model argument is removed. |
| B3 Purchasing reorder | Stays senderless (it is a system trigger) but gains a quantity cap read from the same limit the role's other orders use; the role's docs say so. |
| B4 Support damage | `damage` blocks closing without a person, as `safety` does. |
| B5 People Ops lookups | `list_availability` and `list_candidates` require an authorised caller, as the docs say. |
| B6 Bookkeeper reminders | One reminder per invoice per stage is enforced; tests pin the strict behaviour. |

| B8 Operations approval facts | Gated tools get an `approvalFacts` reader so the approver sees names, dates and amounts. |
| B9 completion evidence | Left: nothing runs evidence yet; fix it when evidence is wired. |

| B12 `people` table | The runtime loads people from the company record at start (upsert), so approvals have an addressee. |

## F. Inefficiencies

All done: wait checkpoints only on change; Paper adapters parse a package once per call;
`LocalVersionedState` validates once per version and walks ancestors linearly; `officehum board`
reads the last sequence number and counts in SQL; Google Calendar `listBookings` asks only for the
window it needs; the inbound inbox prepares its statements once.

## Order

1. In parallel: SDK and role factory; relay, board and extension; the rest of `@officehum/office`;
   gateway, protocol, client and channels; Paper tools.
2. In parallel: the nine roles (three groups); CLI, connectors and host wiring.
3. Typechecked tests (C3, D4), then docs (C1, C6, C7).
4. `npm run check` with the Paper worker provisioned, PR, issues for everything marked "left".
