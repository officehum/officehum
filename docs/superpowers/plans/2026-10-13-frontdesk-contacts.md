# Front Desk contact management implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` for the selected GPT-5.6 Sol implementation / GPT-6.1 Sol review split. One coherent code task; autonomous execution is authorized without additional routine review pauses.

**Goal:** Discover, create and correct durable contacts, then explicitly link approved bookings to stable contact identities.

**Architecture:** Front Desk owns a session-scoped Pi Durable document and replay-safe approved tools. Optional booking identity is pinned in the existing tool memo before calendar effects and linked through a document commit afterward; hosts retain their existing provider/storage boundaries.

**Tech Stack:** TypeScript, Node >=22.19.0, Pi Durable 1.0.2, existing SDK approval gate, Vitest; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-13-frontdesk-contacts-design.md` (read in full).

## Global constraints

- Preserve free-text book calls, both calendar backends, UTC scheduling policy, persisted model/conversation identity, and role portability.
- No implicit message parsing, name-as-identity inference, notes, archive/deletion, outreach, Google Contacts/OAuth, live writes, deployment, or SQLite/schema migration.
- New profile writes require unconditional manifest approval. Keys derive only from conversation/task/call identity; no mutation CLI bypass.
- Use temporary synthetic state only. Controller handles commits, PR/CI/merge and Linear RASF-3255; RASF-3130 stays open.

## Review focus

1. Parallel duplicate-channel creates and competing same-revision updates must yield one winner without lost data.
2. Cleared/omitted channels and same-name people must never collapse identities or preserve a cleared value accidentally.
3. Replay after correction returns an explicitly historical receipt, never overwrites current profile or increments revision.
4. Calendar success before link commit must recover the exact selected identity with one booking/link/decision even after a rename.
5. Existing explicit tool selections and overlay removal masks must gain only permitted contact tools without root/model replacement.
