OPEN-SOURCE MULTI-AGENT OFFICE · REPOSITORY GUIDE

An office made of durable roles.

Office Hum packages specialized agents that can run alone or, as the platform grows, work together for a business. Pi Durable runs the agents and remembers what happened. Office Hum supplies the roles, tools, services, policy, and operator interfaces. Paper Instruments supplies the default model and the planned Word, PowerPoint, and Excel document engine.

Source, not a live office rollout

The current proof is a local Front Desk CLI. The shared workboard, relay, web surfaces, and Office document workflow are designed but not yet delivered. This page separates those states throughout.

Who does what

Three boundaries keep the system understandable. The model proposes work; Pi Durable controls the agent run and recovery; Office Hum decides which role, tool, file, connector, and review path is available.

MODEL, DOCUMENT AND DATA SIDE

Paper is a provider and engine

Paper Instruments is integrated at two distinct points; it is never a second agent harness.

BUILTUltramarine 1 Flash

Paper API through a pi-ai provider. Default for new live Front Desk roots; saved roots retain their pinned provider.

PLANNEDPaper Python forks

paper-docx, paper-pptx, and paper-xlsx inside a restricted, version-pinned worker.

BUILTVersioned FileStore SDK

Immutable versions, operation receipts and replay, stale-edit conflicts, and conditional publish pointer.

PLANNEDDurable Office storage

Production leases, reconciliation, backups, quotas, previews, and exact-version publication.

The authority split: Pi Durable owns conversation and approval/recovery state. FileStore owns bytes, versions, and receipts. Office Hum's future DocumentService joins them by stable operation IDs and policy checks; Paper's worker only executes bounded document operations.

Office Hum

Defines roles and tools, injects connectors, applies leases and business policy, coordinates teams, and presents approval and configuration interfaces.

Host and product layer

Pi Durable

Runs the only agent loop. Its persisted root, tasks, tool results, approvals, and recovery make a request resumable after interruption.

Execution authority

Paper Instruments

Ultramarine supplies model responses through pi-ai. Paper's Python forks are selected as the planned Office document libraries.

How a request moves

Switch between a working Front Desk request and the approved Office document design. The latter is a contract for the next implementation slices, not a claim that Word, PowerPoint, or Excel tools already run.

The interface is a set of surfaces

Office Hum's platform interface spans the operator's command and review screens, each role's portable package, and the host service boundary. The local CLI is the implemented operator surface today.

BUILT

Operator CLI

A person runs one role package, or starts and resumes a durable request, reviews an approval prompt, lists bookings and contacts, and inspects metadata-only inbound email receipts.

  • Run a role package (officehum run) with terminal approvals
  • Grade a role's evals on a bare Pi Durable harness (officehum eval)
  • Credential-free synthetic demo
  • Paper live default; explicit OpenAI override
PLANNED

Workboard and review

The future team surface will show hand-offs, task evidence, document proposals, previews/diffs, exact-version approvals, and publication results.

  • Review binds source and proposed hashes
  • Existing-file edits wait for a person
  • Publish uses a conditional pointer change
PLANNED

Studio and portal

Businesses will tune roles through overlays and plain-language configuration while the installed role package remains portable and unchanged.

  • Instructions, skills, tool switches, model choice
  • Vetted catalog and connector setup
  • Diff and approval before configuration applies
BUILT

Role package

A role is a Pi Durable agent made of instructions, skills, manifest, tools, and evals. The SDK validates package boundaries and lets a bare harness install it.

  • Front Desk is the working role
  • Overlay changes context without modifying package
  • Tool replay and approval behavior are explicit
BUILT

Host connectors

Front Desk tools use injected calendar and Messenger interfaces. The host can select local SQLite or Google Calendar, console outbox or opt-in Resend.

  • Signed inbound Resend intake
  • Exact contact and transport identity
  • Provider acceptance is not delivery proof
PLANNED

Document workspace

Each role may receive typed Paper Office tools and restricted Python only when the task grants a file lease. The worker sees leased versions and staging output, not arbitrary host paths.

  • Word, PowerPoint, Excel adapters
  • Deterministic validation before commit
  • Portable pack, host-supplied service

Drafts and publication are different states.

The versioned SDK can create drafts and move a published pointer, but only the future host service can verify that an existing business file's exact proposal was reviewed by a person. Do not treat the SDK method alone as an approval gate.

Find the parts in the repository

Packages define clean boundaries: portable roles and SDK contracts are usable without the Office Hum host; the host and CLI provide local execution, connectors, and the user-facing command surface.

agents/frontdesk/

Working portable role: instructions, manifest, skills, tools, and tests for the solo Front Desk.

packages/sdk/

Role/package validation, approval helpers, file references, and the versioned FileStore contract and local implementation.

packages/office/

Current solo host adapters: Pi Durable runtime, local calendar, messaging, Resend inbound/outbound, and ownership/state handling.

packages/cli/

Commands, approvals, and state selection.

packages/provider-paper/

Portable pi-ai provider for Paper's Ultramarine 1 Flash, usable in a bare Pi Durable install.

packages/google-calendar/

Portable Google Calendar REST client and test doubles behind the scheduling interface.

Paper Office pack + worker

Approved design, not yet a package here. It will inject DocumentService and invoke restricted Paper Python libraries through the host.

Try the proof that exists

The synthetic demo needs no model or connector key. It exercises the current Front Desk path and leaves a resumable local state directory.

Local Front Desk · credential-free
npm install
npm run build
node packages/cli/dist/index.js demo \
  --state .officehum/frontdesk-demo \
  --approval allow
node packages/cli/dist/index.js bookings \
  --state .officehum/frontdesk-demo
node packages/cli/dist/index.js resume \
  --state .officehum/frontdesk-demo

What this proves

The demo runs a synthetic request, records decisions and effects, and can resume from durable state. Live mode uses Paper's model by default and requires a process-environment credential; it has not been shown here as a production deployment.
